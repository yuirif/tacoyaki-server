# 타코야키 박스 서버

타코야키 박스로 친구들과 세션을 하려면 **모두가 접속할 서버 하나**가 필요합니다. 이 폴더가 그 서버예요.
서버를 켜면 **주소(예: `https://...`)** 가 하나 생기고, 그 주소를 앱의 **\[접속\]** 칸에 넣으면 끝입니다.

> 서버는 **한 명만** 켜면 됩니다(보통 GM). 나머지 친구들은 앱에 그 주소만 넣으면 돼요.

> 🆕 **설치 없이 브라우저로도 접속됩니다(웹판).** 이 폴더의 `webdist` 덕분에, 서버 주소를 브라우저(크롬·엣지·사파리)로
> 열면 바로 접속 화면이 떠요. **아이폰·아이패드·맥** 친구도 같은 주소로 함께 플레이할 수 있습니다.
> (확장팩·자동 로그인·채팅 PNG 저장은 PC 설치판 전용이고, 모바일 전용 화면은 이후 업데이트 예정)

---

## 가장 쉬운 두 가지 길

### 길 A. 내 PC에서 바로 (무료 · 더블클릭 한 번)

이 폴더의 **`타코야키-서버-시작.bat`** 을 더블클릭하세요. 그러면 알아서:

1. 필요한 것(Node.js)이 있는지 확인하고,
2. 서버를 설치·실행하고,
3. **친구들이 접속할 공개 주소(`https://....trycloudflare.com`)** 를 만들어 화면에 띄워줍니다.

화면에 뜬 주소를 복사해 앱의 **\[접속\]** 칸에 넣으면 됩니다.

- ⚠️ Node.js가 없다면 자동으로 [nodejs.org](https://nodejs.org) 를 열어줘요. **LTS** 버전을 설치(다음다음)한 뒤 `.bat` 을 다시 더블클릭하세요.
- ⚠️ **그 창을 켜 두는 동안에만** 친구들이 접속할 수 있어요(내 PC가 서버라서). 창을 닫거나 PC를 끄면 서버도 꺼집니다.
- ⚠️ 무료 방식이라 **실행할 때마다 주소가 바뀝니다.** 매번 새 주소를 친구들에게 알려주세요. 늘 같은 주소로 24시간 돌리고 싶다면 **길 B**를 쓰세요.

### 길 B. 클라우드에서 24시간 (Railway · 월 약 $5)

PC를 꺼도 서버가 살아 있고, 주소도 **고정**됩니다. 아래 버튼으로 시작하세요.

[![Deploy on Railway](https://railway.com/button.svg)](https://railway.com/new)

1. 이 폴더를 **내 깃허브(GitHub)** 에 올린 뒤(아래 「깃허브에 올리기」 참고), Railway에서 **New Project → Deploy from GitHub repo** 로 그 저장소를 고릅니다.
2. ⚠️ **꼭** 서비스에 **볼륨(Volume)** 을 추가하고 **Mount path** 를 정확히 **`/app/data`** 로 지정하세요. (이걸 안 하면 재시작 때 계정·세션이 다 사라집니다.)
3. **Settings → Networking → Generate Domain** 으로 주소를 만들어, `주소/health` 가 `{"ok":true}` 면 성공.

더 자세한 그림 설명은 함께 받은 **「서버 호스팅 가이드」** 문서를 보세요(무료 Oracle·Render·내 PC 방법도 있습니다).

---

## 깃허브에 올리기 (길 B에서 씀)

1. [github.com](https://github.com) 가입 → 오른쪽 위 **+ → New repository** → 이름 입력 → **Public** → **Create**.
2. **uploading an existing file** 링크 → 이 폴더 **안의 파일들**(`Dockerfile`, `package.json`, `src`, `webdist` 등)을 끌어다 놓습니다.
   - `webdist` 폴더까지 올려야 **브라우저 접속(웹판)** 이 됩니다.
   - ⚠️ `node_modules`, `cloudflared.exe` 같은 무거운 파일은 빼고 올리세요(없어도 됩니다).
3. **Commit changes**. 이제 이 저장소를 Railway에 연결하면 됩니다.

---

## 🔄 서버 업데이트하는 법 (앱을 새로 받았다면 서버도!)

앱(설치본)이 새 버전으로 배포되면 **서버도 함께 갱신**해야 합니다. 서버가 옛 판이면 새 기능이
빠지고, 로그인할 때 **“접속한 서버가 옛 판입니다”** 안내가 한 번 뜹니다.

> 🔎 **앱을 지웠다 다시 깔아도 그 안내는 사라지지 않습니다.** 그 창은 프로그램이 아니라 **접속한
> 서버**에 대한 것이기 때문입니다. 서버 주소도 앱에 저장돼 있어 재설치해도 같은 서버를 가리킵니다.
> 창에 적힌 주소로 `주소/health` 를 열어 `ver` 날짜를 확인한 뒤, 아래 절차로 **서버만** 갱신하세요.

- **길 A(내 PC)로 쓰는 중이라면**: 새로 받은 서버 폴더로 이 폴더를 통째로 바꾸고, 원래 폴더의 **`data` 폴더만** 새 폴더로 옮겨 넣은 뒤 `.bat` 을 다시 실행하면 끝. (`data` 가 계정·세션 전부입니다.)
- **길 B(Railway)로 쓰는 중이라면**:
  1. 깃허브의 내 보관함(`tacoyaki-server`)을 열고 → **Add file → Upload files** 로 새 서버 폴더 **안의 파일들을 전부** 끌어다 놓습니다(같은 이름 파일은 새것으로 덮여요).
  2. **Commit changes** 를 누르면 Railway가 **자동으로 다시 배포**합니다(1~3분).
  3. `주소/health` 를 열어 `"ver":"날짜"` 를 확인하세요. 새 서버 폴더의 배포 날짜와 같으면 최신입니다.
  - ⚠️ **올렸는데 `ver` 날짜가 그대로라면** 대시보드에서 최근 배포가 **초록색(Success)** 인지 보세요.
    빌드가 실패하면 Railway 는 **직전에 성공한 배포를 계속 돌립니다**. 겉으로는 올라간 것처럼 보입니다.
    그다음으로 흔한 원인은 ① Railway 가 보는 브랜치(보통 `main`)가 아닌 곳에 커밋, ② `Dockerfile` 이
    저장소 맨 위에 없음(폴더째 올렸다면 Settings → **Root Directory** 에 그 폴더 이름을 적어 주세요).
  - 💾 걱정 마세요: 계정·세션·이미지는 **볼륨(`/app/data`)** 에 있어서 업데이트해도 그대로 남습니다.
  - ⚠️ **단, 서비스를 새로 만들면 볼륨은 따라오지 않습니다.** 위 깃허브 덮어쓰기 방식은 안전하지만,
    Railway CLI 로 올리는 분은 `railway init`(새로 만들기)이 아니라 **`railway link`(쓰던 것에 연결)** 를 쓰세요.
    올린 뒤 계정이 사라져 보인다면 지워진 게 아니라 **다른 서비스에 올린 것**입니다. 대시보드에서 예전 프로젝트를 찾아보세요.

### 올린 뒤 확인하는 법

서버 시작 로그에 이 줄이 보입니다.

```
[data] 영속 폴더: /app/data
```

바로 아래에 `[data] ⚠ 이 폴더가 비어 있습니다` 경고가 **함께** 뜨면 볼륨이 안 붙은 것입니다.
처음 켜는 서버라면 정상이지만, 쓰던 서버인데 이 줄이 보이면 그대로 두지 마세요.
다음 배포에 지금 쌓인 것까지 사라집니다. 마운트 경로가 `/app/data` 인지 먼저 확인하세요.

## 알아두기

- 서버 데이터(계정·세션방·캐릭터·업로드 이미지)는 **`data` 폴더**(클라우드에서는 `/app/data`)에 저장됩니다.
- `data` 폴더에는 **비밀번호 등 개인정보**가 들어가니 **절대 깃허브에 올리지 마세요.** (`.gitignore` 가 막아주지만, 웹에서 직접 끌어 올릴 땐 빼고 올리세요.)
- 환경변수(선택): `SESSION_TTL_DAYS`(로그인 유지일, 기본 30), `CORS_ORIGINS`(허용 주소, 기본 전체),
  `DATA_DIR`(데이터 폴더 위치. 볼륨을 `/app/data` 가 아닌 곳에 붙였을 때만). 그대로 둬도 됩니다.
- 세션방의 대화는 방 하나당 **20,000건**까지 보관합니다. 그보다 오래된 것부터 지워지니,
  긴 이야기를 여러 부로 나눠 진행한다면 부를 넘길 때마다 채팅창의 **로그 저장**으로 받아 두세요.
